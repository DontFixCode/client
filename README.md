# 버스로 🚌

대전 버스 경로·환승 평가를 비교하는 Flutter 앱입니다. 기존 목업을 유지하면서 `../capstone-backend`의 구현된 FastAPI와 Supabase Auth에 연결했습니다. **기본 실행은 서버 연동 모드**이며, 예시 데이터로 자동 대체하지 않습니다.

연동 기준은 2026-11-13 로컬 백엔드 `3202017`입니다. [노션 기능 사양](https://app.notion.com/p/4kang/Function-3f6eeac83dec801eaa94e003ce22654d)의 전체 설계가 구현된 상태는 아니며, 아래 기능과 미구현 API를 구분합니다.

## 실행

앱을 시작하면 `config/backend.local.json`을 자동으로 읽습니다. 현재 작업 공간에는 공개 서버 주소와 anon 키를 설정했습니다. `API_BASE_URL`과 `SUPABASE_URL`은 모두 `https://121.153.148.189:18443`이며 SSH 터널 없이 접속합니다. 새로 체크아웃한 환경에서는 빌드·테스트 전에 `config/backend.example.json`을 `config/backend.local.json`으로 복사하고 실제 주소·공개 키를 입력하세요.

```sh
flutter pub get
flutter run
```

VS Code에서는 `client` 폴더를 열고 실행 구성 **버스로 (서버 연결)** 을 선택해 F5로 실행해도 됩니다. `--dart-define` 또는 `--dart-define-from-file`을 지정하면 해당 값이 로컬 파일보다 우선합니다. 설정 파일이나 실행 옵션을 바꾼 뒤에는 앱을 종료하고 다시 실행하세요.

`API_BASE_URL`은 `/api/v1`을 제외한 FastAPI 주소입니다. `SUPABASE_URL`은 `/auth/v1`을 제외한 Supabase 게이트웨이 주소입니다. `SUPABASE_ANON_KEY`에는 공개 클라이언트 키만 넣으세요. 로컬 설정 파일은 Git에서 제외되지만 앱 자산에는 포함됩니다. 관리자 키·service_role 키·JWT 서명 비밀키를 넣으면 안 됩니다.

- iOS 시뮬레이터·macOS: 로컬 서버라면 `localhost` 사용.
- Android 에뮬레이터: 호스트 컴퓨터는 `10.0.2.2` 사용.
- 실기기: 접근 가능한 서버 주소 사용. 배포 빌드는 HTTPS 사용. Android 디버그 빌드만 HTTP를 허용합니다.
- 이메일 인증·재설정: Supabase의 허용 Redirect URL에 `AUTH_REDIRECT_URL`을 등록해야 합니다. 모바일 기본 예시는 `busro://auth-callback`입니다. SMTP·메일 링크·배포 URL 설정은 서버 운영 환경에서 확인해야 합니다. 모바일 인증 링크는 SDK 플러그인이 처리하도록 [Flutter 기본 딥링크 처리와 중복되지 않게 설정](https://docs.flutter.dev/ui/navigation/deep-linking#migrating-from-plugin-based-deep-linking)했습니다.

기존 목업만 실행하려면:

```sh
flutter run --dart-define=DEMO_MODE=true
```

체험 데이터·체험 계정은 이 모드에서만 사용합니다. 실제 인증 실패·검색 실패 시 체험 계정이나 예시 경로로 넘어가지 않습니다.

## UI 업데이트와 지도

`origin/UI_week1`의 `fd3badc` UI 변경을 기존 서버 연동 코드에 반영했습니다. 도착정보 행·정류장 지도·로그아웃 후 시작 화면 이동을 적용하며, 예시 도착정보는 체험 모드에서만 표시합니다. 실제 로그인·경로 검색·이동 안내·기록은 기존 API를 사용합니다.

카카오 지도 키는 아직 제공받지 않았습니다. 담당자에게 **네이티브 앱 키**를 받은 뒤 `config/backend.local.json`에 `"KAKAO_NATIVE_KEY": "받은 키"`를 추가하고 앱을 다시 실행하세요. 카카오 개발자 설정에서 해당 앱의 Android 패키지·키 해시와 iOS Bundle ID 등록도 필요합니다. 키가 없으면 기존 개념도를 사용합니다. 이 브랜치의 카카오 지도 적용 범위는 Android/iOS의 체험 정류장 위치 표시이며, 실제 경로의 서버 형상 표시와 웹 지도는 별도입니다.

실제 모드에서는 홈에 들어갈 때 출발지가 비어 있으면 위치 권한을 확인하고 현재 위치를 출발지로 설정합니다. 권한 거부·위치 서비스 꺼짐·위치 조회 실패 시 직접 선택하거나 다시 시도할 수 있습니다. 사용자가 선택한 출발지는 자동 조회 결과로 덮어쓰지 않습니다.

병합 후 정적 검사와 테스트 47개, iOS 시뮬레이터·일반 웹 빌드를 통과했습니다. 시뮬레이터에서 위치 권한 허용 후 출발지가 `현재 위치`로 자동 설정되는 것도 확인했습니다. 카카오 SDK의 WebAssembly 사전 검사에는 경고가 있어 Wasm 빌드는 검증 범위에 포함하지 않았습니다.

## 웹 실행

현재 백엔드에는 CORS 설정이 없습니다. 백엔드 파일을 수정하지 않고 실행할 수 있도록 로컬 프록시를 제공합니다.

1. `config/backend.local.json`을 `config/web.local.json`으로 복사합니다.
2. `API_BASE_URL`, `SUPABASE_URL`을 모두 `http://localhost:3000`, `AUTH_REDIRECT_URL`을 `http://localhost:3000`으로 지정합니다. 공개키는 유지합니다.
3. 아래 명령으로 빌드·실행합니다.

```sh
flutter build web --dart-define-from-file=config/web.local.json
python3 tool/dev_server.py --api https://121.153.148.189:18443 --auth https://121.153.148.189:18443
```

`http://localhost:3000`에 접속합니다. 프록시는 루프백에만 바인딩하며 HTTP와 WebSocket을 전달합니다. 실제 서버 주소에 맞춰 `--api`, `--auth`를 변경하세요. 이 스크립트는 개발용입니다. 운영에서는 HTTPS 역방향 프록시 또는 서버 CORS 설정이 필요합니다.

## 연결한 기능

- Supabase 이메일 로그인·가입·로그아웃·세션 복원·토큰 갱신, 비밀번호 재설정 메일 요청과 링크로 진입한 새 비밀번호 설정.
- FastAPI 회원정보 조회·이름 변경.
- 장소 검색 API, GPS 현재 위치, 좌표 직접 입력. 현재 백엔드의 장소 제공처가 미구현이므로 실제 장소 검색은 503 안내가 나옵니다. GPS·좌표로 경로 검색을 진행할 수 있습니다.
- 경로 검색 202 접수 → 결과 폴링. 자료 부족·지원 구간 밖·경로 없음·검색 오류·만료를 구분합니다. 시간·확률 null을 그대로 표시합니다.
- 직행·다중 환승·도보 구간 표시, 연결별 환승 여유·성공 확률, 추천 후보와 시작 가능 여부.
- 배차간격 기반 예상 경로(`estimated`·`headway_estimate`)와 앞차 기반 ETA 근사를 구분하고, 서버 추천순·제한 사유를 표시합니다. 이동 복원 시에도 구간 ETA의 예상 여부를 유지합니다.
- 이동 시작, 활성 이동 복구, 수동 탑승·하차·탑승 수정·완료·취소. 상태 버전과 중복 방지 키를 전송하며 응답 유실 시 동일 요청으로 재확인합니다.
- WebSocket 첫 메시지 인증, 재접속·앱 재개 시 상태 복구, 오래된 버전의 응답 차단. 앱을 닫거나 로그아웃해도 서버 이동을 취소하지 않습니다.
- 이동 안내에서 다음 승차 정보·탑승 차량 하차 ETA·도착 평가를 확인합니다. 실시간 연결 상태와 예측 자료의 최신성은 구분합니다.
- 사용자 선택에 따른 전경 GPS 위치 전송. 백그라운드 위치 전송은 구현하지 않았습니다.
- 서버 이동 기록 목록·페이지네이션·상세·진행 중 이동 이어보기.
- 주변 정류소, 정류소 상세·경유 노선·도착정보, 노선 검색·상세·패턴·경유 정류소·형상·차량 위치, 정적 공개본 상태 조회.

백엔드는 ODsay 버스 형상을 지원합니다. 배포 설정·노선별 수집 결과에 따라 형상이 없으면 실제 도로를 임의로 그리지 않고 정류소·구간 목록을 제공합니다. 형상이 있으면 제공된 GeoJSON과 출처·상태를 배경 지도 없이 표시합니다. 카카오 지도 SDK는 위 체험 정류장에 연결돼 있으며 실제 경로의 배경 지도에는 아직 적용하지 않았습니다. 도착·차량 정보는 서버 공유 수집본을 조회하며 오래된 자료·수집 실패·기준 시각 미확인을 구분합니다.

## 남은 기능과 검증

[연동 결과와 백엔드 요청 사항](docs/backend-integration.md)에 API 대응, 변경 내용, 미구현 기능과 담당자에게 받을 정보를 정리했습니다. 장소 검색 제공처, 이동 중 대안·놓친 버스·목적지 변경, 환승 결과 제출, 회원/기록 삭제, 하차·환승 알림은 아직 백엔드 구현 또는 계약 확정이 필요합니다.

공개 HTTPS 주소에서 기존 계정 로그인과 인증된 프로필 조회, WebSocket 연결 수립을 확인했습니다. iOS 시뮬레이터에서도 설정 파일을 포함한 빌드로 기존 계정 로그인·회원정보 표시·로그아웃을 확인했습니다. 신규 가입·메일 링크·실제 여정 스트림과 전체 이동 흐름은 추가 검증이 필요합니다. 검색 검증에는 배포 버전과 재현용 경로·교통 데이터가 필요합니다.

```sh
flutter analyze
flutter test
flutter build web
python3 -m unittest discover -s tool -p 'test_*.py'
```

`test/backend_integration_test.dart`는 백엔드 코드의 응답 계약에 맞춘 HTTP·인증 SDK·스트림 대역을 사용합니다. 실제 DB·공공 교통 API·SMTP·기기 권한을 통과한 현장 E2E 검증과는 구분해야 합니다.
